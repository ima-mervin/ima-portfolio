Overview

Cardinali-Tea and Coffee is a local coffee shop whose data lived in disconnected systems — employee schedules, inventory labels, supplier contacts, and customer orders all separate, making accurate reporting hard. We designed an entity-relationship model and SQL database that maps how every part of the shop relates, eliminating redundant data and giving managers one cohesive source of truth.

Core concepts

  • Entity-relationship design — modeled employees, shifts, baristas/managers, equipment, suppliers, inventory, menu, orders, customers, and payments with keys and cardinalities
  • Normalized schema mapping — translated the ERD into ~15 relations with primary/foreign keys and junction tables for many-to-many links
  • Analytical SQL — wrote queries for top employees by revenue, high-value repeat customers, and best-selling menu items by category and allergen
  • Reporting layer — surfaced results in Tableau (revenue by employee, revenue distribution across menu allergens)

Development notes

With the schema in place, analytical queries answer real operational questions — for example, ranking the top menu items by quantity sold and revenue, including allergen and category:

SELECT mn.MenuID, mn.ProductCategory, mn.Price,
       SUM(o.Quantity) AS total_qty_sold,
       SUM(o.Quantity * mn.Price) AS total_revenue
FROM Menu mn
JOIN OrderMenu om ON mn.MenuID = om.MenuID
JOIN Orders o ON om.OrderID = o.OrderID
GROUP BY mn.MenuID, mn.ProductCategory, mn.Price
ORDER BY total_qty_sold DESC
LIMIT 5;
"Organizing scattered operations into one cohesive database eliminates redundancy, improves accuracy, and streamlines the day-to-day."

The dataset was generated with Mockaroo from realistic coffee-shop schemas, letting the team validate the design and queries against representative records before any production rollout.
